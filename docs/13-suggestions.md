# 13 — Dynamic suggestions

Follow-up prompt suggestions are **generated by the model**, not hard-coded. After
a turn settles the frontend asks the backend for 3–4 short prompts grounded in
the recent conversation, the current Grafana page, and free-text guidance the
user has given us ("custom context").

This replaced the old static `buildPrefill()` helper (a fixed string per page
kind, e.g. *"Explain what my current Explore query is doing…"*), which could not
react to what had actually been discussed.

## Endpoint — `POST /api/plugins/mcpagent-app/resources/suggestions`

`Content-Type: application/json`, `Accept: application/json`. Not streamed.

```ts
type SuggestionsRequest = {
  history?: Array<{ role: 'user' | 'assistant'; content: string }>;  // oldest first, capped client-side
  pageContext?: PageContext;                                          // see 06-page-context.md
  customContext?: string;                                             // user-provided guidance
};

type SuggestionsResponse = { suggestions: string[] };
```

Backend structs (`pkg/plugin/resources.go`):

```go
type suggestRequest struct {
    History       []agent.Turn `json:"history"`
    PageContext   *pageContext `json:"pageContext"`
    CustomContext string       `json:"customContext"`
}

type suggestResponse struct {
    Suggestions []string `json:"suggestions"`
}
```

### `handleSuggestions`

**Best-effort by design**: every failure path (non-`POST`, undecodable body,
Bedrock error) returns **HTTP 200 with `{"suggestions":[]}`** so the UI simply
renders no chips instead of surfacing an error in a non-essential feature.
Bedrock errors are logged at `Warn`. `suggestions` is never `null` on the wire
(`writeSuggestions` normalizes to `[]`).

Page context is rendered with the same `contextBody()` helper used by
`enrichWithContext`, so suggestions see exactly what the chat prompt sees.

## Model call — `pkg/agent/suggest.go`

`Agent.Suggest(ctx, history, contextText, customContext) ([]string, error)`:

- Non-streaming **`Converse`** (not `ConverseStream`) — the caller needs the whole
  JSON array before it can respond.
- **No `ToolConfig`**: suggestions must never trigger MCP or browser tool calls.
- `InferenceConfig`: `MaxTokens: 400`, `Temperature: 0.4` (low, for stable,
  grounded output).
- Same model id as chat (`Settings.ModelID`, default
  `us.anthropic.claude-sonnet-4-5-20250929-v1:0`), so a Sonnet-class model
  handles both.

### Prompt shape

`suggestSystemPrompt` instructs the model to return **only** a compact JSON array
of 3–4 strings, each specific, grounded, phrased as the user's next message,
≤ ~90 chars, and distinct from what was already asked.

`buildSuggestPrompt` assembles one user message from the parts that exist:

```
[User-provided guidance]
<customContext>

[Grafana page context]
<contextBody(pageContext)>

[Recent conversation]
User: <...>
Assistant: <...>

Suggest the user's next prompts as a JSON array of strings.
```

### Parsing — `parseSuggestions`

Defensive on purpose (models occasionally add prose or code fences):

1. Slice from the first `[` to the last `]`; no array → `nil`.
2. `json.Unmarshal` into `[]string`; malformed → `nil`.
3. Trim entries, drop blanks, cap at `maxSuggestions` (**4**).

Covered by `pkg/agent/suggest_test.go` (clean array, fenced/prose-wrapped,
blank-dropping, capping, no-array, malformed).

## Frontend

- `lib/chat-stream.ts` → `fetchSuggestions(request, signal)`: abortable; resolves
  to `[]` on any error so callers need no error branch.
- `components/ChatPanel.tsx`:
  - State: `suggestions: string[]`, `suggesting: boolean`, `customContext: string`,
    `customContextOpen: boolean`, plus `suggestAbortRef`.
  - `refreshSuggestions(msgs, ctx)` sends the **last 10 non-empty messages**,
    current page context, and trimmed custom context. It aborts any in-flight
    request so only the newest wins, and short-circuits to `[]` when there is
    neither history nor page context to ground on.
  - Trigger: an effect that runs only when **`!busy`**, **debounced 400ms** (so
    the streaming-settle + context-re-extract burst collapses into one call),
    keyed on `messages`, `pageContext`, `activeId`, and `customContext`. So
    suggestions refresh on load, after every answer, on navigation, on new chat,
    and when guidance changes.
  - Render: a column of tappable dashed chips (`styles.suggestionRow` /
    `styles.suggestion`, `data-testid="mcpagent-suggestions"` on the row and
    `mcpagent-suggestion` per chip). Tapping fills the composer — the input is
    **never** pre-seeded. Chips hide once the user types, while `busy`, and while
    an interaction (confirm / `ask_user`) is pending.
  - While a request is in flight, `Thinking of suggestions…` renders next to the
    custom-context toggle.

### Steer suggestions (standing user preference)

A free-text field under the composer behind a `Steer suggestions` disclosure
(`data-testid="mcpagent-customcontext-toggle"` / `-input`). The toggle label
gets a `•` marker when non-empty and starts **expanded** when a preference is
already saved. The label deliberately avoids "custom context" so it isn't
mistaken for the operator-level context set via Helm/env.

- Owned by `lib/use-custom-context.ts` (`useCustomContext()`), backed by
  `chat-store.ts` `loadCustomContext()` / `saveCustomContext()` /
  `subscribeCustomContext()` under key **`mcpagent.customContext.v1`**.
- **Consistency guarantees** — the value is the same regardless of surface:
  - survives page reloads and Grafana navigations (localStorage, own key);
  - survives the drawer closing (which unmounts `ChatPanel` entirely);
  - is shared across chat sessions, and is untouched by New chat / deleting
    history (it is *not* inside the `mcpagent.chat.v1` blob);
  - propagates live to any other mounted panel in the tab via a
    `mcpagent:customContext` `CustomEvent`, and to other Grafana tabs via the
    native `storage` event.
- Sent as `customContext` on every suggestions request; editing it re-triggers
  generation.

> Distinct from the operator-level **per-MCP-server `Context`** in
> [08-config.md](./08-config.md), which is admin-configured and injected into the
> chat system prompt. This one is end-user, client-side, and steers suggestions.

## Cost / latency notes

One extra non-streaming model call per settled turn. Bounded by: `MaxTokens: 400`,
the 10-message history cap, 400ms debounce, abort-on-supersede, and the idle-only
(`!busy`) trigger.

## Gaps / not-yet-implemented

- No caching: navigating back to a previously-seen page re-generates suggestions.
- Custom context is **not** sent to the chat turn itself, only to suggestions.
- Suggestion quality isn't evaluated; there are no assertions on model output
  beyond shape (`parseSuggestions`).
